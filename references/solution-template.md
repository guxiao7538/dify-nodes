# 搭建方案文档模板

产出 Dify 搭建方案文档时严格套用本模板。方案的读者可能不熟悉技术术语,文档的目标是:读者对照文档即可在 Dify 画布上独立完成搭建。

## 行文规范

1. 正式、中性、面向任何读者。不出现对话式表述(如"根据你的要求""我已经为你"),不出现对编写过程的描述。
2. 每个配置项给出**具体取值**(示例:"温度填 `0.3`"),不写"设置一个合适的值"。取值来自需求;需求未覆盖的按合理默认取值并在该配置项旁注明理由。
3. 术语首次出现时用一句话解释(如:迭代节点——对一组数据逐条执行相同处理)。
4. 知识库、工具插件、模型供应商等外部资源不由方案生成,一律写入「前置准备」,注明在 Dify 中的准备路径。
5. 全文使用中文,字段名、代码、DSL 键名保留英文原文并加反引号。

## 文字流程图规范

- 用缩进树 + 箭头表达流程,**不使用 mermaid 或其他图表语法**。
- 每个节点一行,格式:`【节点类型】节点标题`,与后文小节的编号对应。
- 分支用 `├─` 与 `└─` 标注,分支条件写在同一行。

示例:

```text
【开始】用户输入:合同文本
   ↓
【文档提取器】提取合同正文
   ↓
【代码执行】清洗与截断正文
   ↓
【LLM】提取关键条款
   ↓
【条件分支】是否发现风险条款
   ├─ 是 →【LLM】生成风险说明 →【直接回复】输出风险报告
   └─ 否 →【直接回复】输出"未发现明显风险"
```

## 节点小节格式

每个节点小节固定包含三部分:

1. **基本信息表**:节点类型、节点标题(标题自拟,体现功能,如"内容清洗"而非"代码执行")。
2. **配置项表**:逐项列出界面上需要填写的配置、具体取值、一句话说明。配置项的名称与取值规范以 `node-schemas.md` 对应小节为准;代码节点的代码直接给完整可粘贴代码,以 `code-node.md` 规范为准。
3. **输入与输出**:来自哪个节点(引用写法)、输出给哪个节点(引用写法)、易错点(引用 `node-schemas.md` 中该节点的易错点)。

迭代、循环等多节点容器,先写容器节点的配置,再依次写内部节点小节,内部小节注明"位于 4.x 迭代内部"。

## 交付要求

- 文件名:`dify-<应用名>-搭建方案.md`;写入使用者指定的目录,未指定时写入当前工作目录。
- 交付时附一句说明:文档位置、「导入说明」中声明了可生成 DSL。
